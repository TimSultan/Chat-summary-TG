# Как выкатывать обновления

Игра живёт на Railway. Пуш в `master` деплоится автоматически и сразу, на живых игроках.
Этот документ — про то, как делать это без «ой».

---

## Коротко

```bash
# 1. локально: тесты
python -m pytest tests/ -q

# 2. локально: новый код против КОПИИ боевых данных
python preflight.py ./data-copy/cache/stats/Europe_Moscow

# 3. на сервере: закрыть игру
python admin_pause.py on --notice "Обновление, минут на пять"

# 4. выкатить
git push

# 5. дождаться деплоя, проверить логи и одну-две кнопки в боте

# 6. открыть
python admin_pause.py off
```

Шаги 3 и 6 нужны **не всегда** — см. «Когда пауза обязательна».

---

## Почему просто «пуш» — плохо

Три разных способа сломать игру, и они требуют разной защиты.

**Код не запускается.** Самый безобидный: сервис падает на старте, никто не успевает
ничего потерять. Ловится тестами и `preflight.py`. Так упал деплой, где `attach()`
передавали параметр, которого у неё не было, — импорт проходил, падало только при
реальном вызове.

**Код работает, но неправильно.** Гидра, в которой невозможно победить. Кулдаун, который
не проверяется. Ловится только тестами и головой — никакой процесс это не поймает.

**Код молча портит данные.** Самый опасный и самый частый здесь. Нормализатор
пересобирает структуру по списку известных полей и **выбрасывает всё остальное**.
Реальные случаи:

- `_normalise_dungeon_run` терял `run_id` → все убийства в подземелье получали один ключ
  лута → 300 убийств дали 0 свитков;
- кошелёк свитков пересобирал `pity` без `"dungeon"` → обещанная гарантия не срабатывала
  ни разу;
- `pets_combat.snapshot()` не сохранял часть полей → повтор боя воспроизводил другое
  существо.

Тесты это не ловят: они создают данные свежим кодом, поэтому теряться нечему.
Ловит **только** прогон старых данных через новый код — это и есть `preflight.py`.

---

## 1. Тесты

```bash
python -m pytest tests/ -q
```

Часть тестов зависит от даты (ежедневная ротация магазина) и может падать не по твоей
вине. Сравнивай со состоянием до своих правок:

```bash
git stash && python -m pytest tests/ -q | tail -15 && git stash pop
```

Если список падений одинаковый — ты ничего не сломал.

## 2. Preflight: старые данные через новый код

Самая ценная проверка. Скачай копию тома с Railway и натрави на неё:

```bash
python preflight.py ./data-copy/cache/stats/Europe_Moscow
```

Он проверяет три вещи:

1. модули импортируются, и `pets_web.attach()` принимает всё, что ей передаёт
   `bot_listener` (тот самый краш на старте);
2. каждое хранилище загружается новым кодом без исключения;
3. **load → save ничего не теряет** — ни одного поля, ни одного элемента списка, ни одной
   монеты.

Вывод либо

```
✅ Годно к выкатке: старые данные читаются новым кодом без потерь.
```

либо

```
❌ ПОТЕРЯНО  pets.1.dungeon_run.run_id = 'abc123'
❌ НЕ ВЫКАТЫВАТЬ
```

**«ПОТЕРЯНО» и «УКОРОЧЕНО» — это стоп.** Чинить нужно нормализатор, а не данные.

Ничего не пишет в папку, которую ему дали, но всё равно давай ему **копию**: инструмент
безопасности, способный испортить продакшен, — не инструмент безопасности.

## 3. Пауза

```bash
python admin_pause.py on --notice "Обновление, минут на пять"
python admin_pause.py status
python admin_pause.py off
```

Или в мини-приложении: **Ещё → ⚠️ Пауза игры** (виден только админам чата).

Что делает пауза:

- **не даёт начать** бой, забег, покупку, смену — и в вебе, и в боте;
- **не трогает то, что уже идёт**: ферма и карьер считаются по таймстампам в момент
  чтения, поэтому пауза их не оплачивает раньше времени и не теряет;
- **не мешает читать**: существо, сумка, рейтинг и объяснение остаются на месте.

Флаг лежит **файлом на томе**, а не в переменной окружения. Это принципиально: смена
переменной окружения — это и есть рестарт, то есть ты бы перезапускал сервис вокруг того
самого перезапуска, который пытался обезопасить. Файл переживает рестарт и переключается,
пока новый код поднимается.

Если файл повреждён — игра считается **открытой**. Механизм, который защищает от простоя,
не должен сам его устраивать.

### Когда пауза обязательна

| Что меняешь | Пауза |
|---|---|
| Тексты, баланс чисел, новые предметы | не нужна |
| Логика боя, наград, лута | желательна |
| **Форму хранимых данных, нормализаторы, миграции при старте** | **обязательна** |
| Одноразовые выдачи/возвраты при старте (`retire_*`) | **обязательна + бэкап** |

Последняя строка — единственный необратимый случай: миграция выполняется на старте и
откат кода её **не отменяет**. Перед такими релизами делай снапшот тома.

## 4. Деплой и проверка

```bash
git push
```

Смотри логи Railway. После старта проверь в боте: `/arena` открывается, один бой проходит,
ферма показывает верные цифры. Если что-то не так — игра всё ещё на паузе, откатывай
спокойно.

## 5. Открыть

```bash
python admin_pause.py off
```

## Как тестировать до продакшена по-настоящему

Preflight ловит потерю данных, тесты ловят логику. Чего не хватает — **живой игры новым
кодом до того, как его увидят люди**. Это стейджинг, и он стоит одного вечера:

1. второй бот у @BotFather → второй `TELEGRAM_BOT_TOKEN`;
2. отдельный чат на несколько человек;
3. второй сервис на Railway с той же репой, но веткой `staging` и **своим** томом;
4. скопировать туда снапшот боевых данных — тогда играешь на реалистичном состоянии.

Дальше цикл: `staging` → поиграл полчаса → мержишь в `master`.

Именно так ловятся вещи, которые не видит ни один тест: непроходимая гидра, «кнопка не
реагирует», «награда выглядит обидно».

> **Никогда не подключайся боевой Telegram-сессией из локальной машины.** Это может
> навсегда убить ключ авторизации задеплоенного сервиса. Стейджингу — свой токен и своя
> сессия.

## Чего делать не надо

- **Пятничный деплой.** Никто не чинит игру в субботу.
- **Миграция данных и правка баланса в одном коммите.** Когда что-то пойдёт не так, ты не
  сможешь откатить одно, не откатив другое.
- **Считать успешный `import` проверкой.** Всё, что упоминается внутри тела функции,
  падает только при вызове — то есть в продакшене. Проверяй `grep`'ом каждый кусок, а не
  импортом целиком.
- **Пакетные правки одним скриптом с `assert` и записью в конце.** Один непопавший шаблон
  — и не сохраняется **ничего**, а выглядит как «упала одна правка». Так и произошло с
  `attach()`.
